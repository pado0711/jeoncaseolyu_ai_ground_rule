"AI가 대신 하는 것이 아니라,
AI와 함께 더 잘 생각하는 것"
같은 도구라도 쓰는 방식에 따라 결과가 완전히 달라집니다.
핵심 룰
The Rule
AI를 활용한 모든 코드·결과물에는 주석으로 표시하고,
반드시 본인의 말로 설명을 직접 작성해야 합니다.
1
AI 활용 부분을 주석으로 표시한다
어떤 툴을 썼고, 어떤 부분에서 도움받았는지 코드 안에 명시합니다.
# [AI-assisted] Claude — 초안 생성 # 변경 사항: 청킹 단위를 토큰→문장으로 수정, 메타데이터 필드 추가 def chunk_text(text, max_sentences=5): sentences = text.split(".") ...
PR 설명에도 한 줄 기록을 남깁니다.
## AI 활용 Cursor: reranker 함수 skeleton 생성 Claude: 비동기 처리 디버깅 힌트
2
AI가 만든 부분은 반드시 내 설명을 직접 작성한다
주석 표시에서 끝나면 안 됩니다. 왜 이 코드가 동작하는지, 내가 무엇을 수정했는지를 본인의 언어로 적어야 합니다.
❌ 이렇게 말고
# [AI-assisted] Claude로 생성 → 설명 없이 표시만 한 경우
✅ 이렇게
# [AI-assisted] Claude — 초안 생성 # 설명: split()으로 문장 구분 후 # 리스트를 5개씩 묶는 방식. # max_sentences 파라미터로 # 유연하게 조절 가능하게 수정함
3
설명을 못 쓰겠다면, 아직 이해가 부족한 것
설명을 작성하다가 막히는 부분이 있다면 제출 전 반드시 다시 공부합니다.
  • 이 코드가 왜 동작하는지 면접관 앞에서 설명할 수 있나?
  • AI가 만든 코드를 내가 직접 수정할 수 있나?
  • AI 없이 이 문제를 다시 풀 수 있나?
하나라도 '아니오'라면 → 이해 후 다시 작성
단계별 활용 가이드
입문
Python 기초
새 개념은 AI 닫고 먼저 시도. 에러 메시지는 2~3분 직접 읽은 뒤 질문.
심화
API · 알고리즘
의사코드 먼저 설계 → "이 방향 맞아?" / "힌트만 줘" 방식으로 활용.
프로젝트
AI 앱 구현
보일러플레이트는 AI에게. 아키텍처·핵심 로직은 직접 설계하고 발표 때 설명 가능해야 함.
허용 vs 금지
허용
  • 개념 질문
  • 디버깅 힌트 요청
  • 오류 메시지 설명 요청
  • Copilot 자동완성 참고
  • AI 도움받은 부분 주석 명시
금지
  • 과제 전체 생성 후 무검증 제출
  • 설명 없이 AI 코드 그대로 사용
  • 타인 코드를 AI로 변형해 제출
  • 평가 중 AI 실시간 참조
  • AI 생성 내용을 본인 작성으로 허위 주장
판단이 애매할 때
"이걸 AI에게 맡기면, 내가 이 부분에서 뭘 배울 기회를 잃는가?"
이 질문에 "예"가 나오면 AI보다 직접 해결을 먼저 시도합니다.
AI를 더 잘 쓰기 위한 습관
  • 계획 먼저AI에게 시키기 전에 내가 원하는 것을 한 문장으로 정리한다.
  • 맥락 관리대화 맥락이 길어지면 요약해서 새 세션을 시작한다.
  • 검증 필수AI가 만든 코드는 로컬에서 실행해보고 이해한 뒤 팀에 공유한다.
  • 기록 습관어떤 프롬프트로 무엇을 만들었는지 PR 설명에 한 줄이라도 남긴다.
